DevOps & CI/CD Tehnička Dokumentacija

Primena DevOps i CI/CD procesa u razvoju skalabilne web aplikacije

Razvoj full-stack aplikacije (Movie Review & Quality Hub) sa automatizovanim testiranjem (Vitest & Playwright), multi-stage Docker kontejnerizacijom i automatskim GitHub Actions deployment procesom na Cloud infrastrukturu.

Arhitektura React 19 + Express + SQLite
Test Automatizacija Playwright E2E + Vitest
Kontejnerizacija Docker Multi-Stage
CI/CD Pipeline GitHub Actions + Cloud Run

1. Arhitektura Sistema i Tehnološki Stack

Aplikacija je projektovana kao skalabilno monolitno rešenje koje kombinuje klijentski interfejs, REST API rute, bezbednosne mehanizme i ugrađeni statički analizator koda. Svi segmenti su usklađeni sa modernim DevOps standardima.

Korisnički Interfejs (Frontend)

React 19, TypeScript, Vite, Tailwind CSS v4, Motion animacije i Lucide ikonice.

Serverski Sloj (Backend)

Node.js 20 LTS, Express 4.x, TypeScript (tsx za dev, esbuild CJS bundle za produkciju).

Baza & Skladištenje

SQLite integrisan kroz better-sqlite3 sa parametrizovanim prepared statements upitima.

2. Implementacija Korisničkog Interfejsa (Frontend - UI)

Korisnički interfejs u /src direktorijumu nudi čist, moderan i responsivan doživljaj prilagođen i krajnjim korisnicima i DevOps/QA inženjerima.

2.1 Funkcionalni Moduli Aplikacije

  • Autentifikacioni modul (Login / Register): Omogućava prijavu postojećih i registraciju novih korisnika uz klijentsku i serversku validaciju. Uključuje Sandbox Quick-Credentials dugmad za brzo testiranje (@admin, @developer, @reviewer).
  • Katalog filmova (Movie Finder & Reviews): Prikazuje listu filmova sa detaljima (godina, žanr, režiser, ocena, trajanje), pruža filtriranje i pretragu u realnom vremenu, kao i modal za dodavanje i brisanje filmova.
  • Korisnički profil i revizorski logovi (Audit Trail): Prikazuje metapodatke korisnika, omogućava izmenu biografije i lokacije, i nudi uvid u sistemske logove svih akcija (prijava, kreiranje filmova, brisanje, IP adrese).
  • Code Quality & DevOps Hub: Interaktivni editor koji simulira statičku analizu i prikazuje SonarQube ocene (A–E, Quality Gate, tehnički dug, bezbednost), PMD analizu kompleksnosti ($O(N^2)$ petlje) i ESLint stilska pravila.

2.2 Prilagođenost UI-ja za Test Automatizaciju (ID Selektori)

Serverski sloj implementiran u server.ts i src/db.ts obezbeđuje REST API komunikaciju, bezbednost podataka i interakciju sa bazom.

3.2 Bezbednosni Mehanizmi Baze Podataka

Kriptografska Zaštita Lozinki

Korišćenje crypto.createHash('sha256') sa heširanjem unosa. Plain-text lozinke se nikada ne čuvaju u bazi podataka.

Prevencija SQL Injection Napada

Svi SQL upiti se izvršavaju preko pripremljenih iskaza (Prepared Statements) sa parametrima (?), što onemogućava injektovanje koda.

4. Automatizovano Testiranje i Pokrivenost Testovima

Strategija testiranja obuhvata dva nivoa: Jedinične/Integracione testove (Vitest) i End-to-End browser testove (Playwright).

4.1 Jedinični i Integracioni Testovi (src/db.test.ts - Vitest)

Testiraju logiku baze podataka, bezbednost i algoritme:

  • Kriptografski testovi: Provera da li SHA-256 heš ima 64 karaktera, da li je determinističan i usklađen sa Node.js kriptografijom.
  • Autentifikacioni testovi: Validacija dužine korisničkog imena (minimum 3 karaktera) i lozinke (minimum 4 karaktera), provera neuspešnih prijava sa pogrešnom lozinkom i uspešna prijava predefinisanog administratora.
  • CRUD operacije nad filmovima: Kreiranje novog filma, provera postojanja u bazi, ažuriranje podataka i brisanje uz verifikaciju da zapis više ne postoji.
  • Revizorski logovi: Upis i čitanje logova uz verifikaciju IP adresa i akcija korisnika.
# Pokretanje jediničnih testova u terminalu
npm run test

4.2 End-to-End (E2E) Browser Testovi (e2e/auth-and-movies.spec.ts - Playwright)

Playwright podiže realan Chromium pretraživač i automatski prolazi kroz kompletne korisničke tokove:

5. Docker i Kontejnerizacija Aplikacije

Kako bi se garantovala prenosivost i eliminisale razlike između razvojnih i produkcionih okruženja (posebno C++ zavisnosti za better-sqlite3 na Windows-u), kreiran je optimizovani Multi-Stage Dockerfile.

# ── STAGE 1: Build Faza (Kompajliranje aplikacije) ───────────────
FROM node:20-slim AS builder

# Instalacija neophodnih C++ alata za nativno bildovanje SQLite modula
RUN apt-get update && apt-get install -y python3 make g++ && rm -rf /var/lib/apt/lists/*

WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build
RUN npm prune --production

# ── STAGE 2: Produkciono Runtime Okruženje ───────────────────────
FROM node:20-slim AS runner

WORKDIR /app
ENV PORT=3000
ENV NODE_ENV=production

COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package*.json ./

EXPOSE 3000
CMD ["npm", "start"]
Ključne prednosti Multi-Stage kontejnera:

Produkcioni imidž ne sadrži teške build alate (g++, make, python3) niti devDependencies, što smanjuje veličinu kontejnera za preko 65% i eliminiše bezbednosne ranjivosti u produkciji.

6.1 Pravila i Zaštitni Mehanizmi u Pipeline-u

  • Strogi Quality Gate (needs: test-and-lint): Deployment faza se nikada neće pokrenuti ukoliko padne ijedan linter ili test.
  • Slojno keširanje (Buildx Cache): Korišćenje cache-to: type=gha,mode=max ubrzava ponovno bildovanje Docker imidža sa 4 minuta na manje od 40 sekundi.
  • Bezbedna autentifikacija: Korišćenje OpenID Connect (OIDC) / Workload Identity Federation protokola bez skladištenja trajnih administratorskih ključeva u GitHub tajnama.

7. Predlozi za Dalji Razvoj Aplikacije

Za prelazak aplikacije u naprednu enterprise fazu predlažu se sledeća unapređenja:

7.1 Primena Page Object Modela (POM) u Playwright Testovima

Enkapsulacija logike stranica u zasebne klase (npr. LoginPage, MoviePage) povećava čitljivost i olakšava održavanje testova pri izmenama u UI dizajnu.

// e2e/pages/LoginPage.ts
import { Page, Locator } from '@playwright/test';

export class LoginPage {
  readonly page: Page;
  readonly usernameInput: Locator;
  readonly passwordInput: Locator;
  readonly submitButton: Locator;
  readonly adminQuickButton: Locator;

  constructor(page: Page) {
    this.page = page;
    this.usernameInput = page.getByPlaceholder('username');
    this.passwordInput = page.getByPlaceholder('••••••••');
    this.submitButton = page.locator('#btn-submit-auth');
    this.adminQuickButton = page.locator('#btn-prefill-admin');
  }

  async goto() {
    await this.page.goto('/');
  }

  async loginAsAdmin() {
    await this.adminQuickButton.click();
    await this.submitButton.click();
  }
}

7.2 Dodatna Preporučena Unapređenja

Vizuelno Regresiono Testiranje

Uvođenje expect(page).toHaveScreenshot() snapshot testova u Playwright radi automatske detekcije nenamernih promena u CSS stilovima.

Povezivanje sa SonarCloud Serverom

Integracija sonarsource/sonarcloud-github-action koraka u CI/CD za automatsku analizu pokrivenosti koda na svakom Pull Request-u.

Canary & Blue/Green Deployments

Konfigurisanje Cloud Run saobraćajnog splita (npr. 90% stabilna verzija, 10% nova verzija) uz automatski rollback u slučaju porasta HTTP 5xx grešaka.

Migracija na PostgreSQL bazu

Zamena lokalnog SQLite fajla sa visoko dostupnom Cloud SQL (PostgreSQL) bazom i Drizzle ORM migracijama integrisanim u CI/CD pipeline.
